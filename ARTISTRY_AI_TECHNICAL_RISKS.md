## 1. RISK ASSESSMENT METHODOLOGY

Risks are systematically evaluated across 12 technical categories. Each risk is scored according to:
- **Severity:** `CRITICAL` (System crash, data corruption, bricked build) | `HIGH` (Core drawing failure, unrecoverable visual flaw) | `MEDIUM` (Degraded UX, performance hitch) | `LOW` (Minor cosmetic inconsistency).
- **Probability:** `HIGH` (>50% likelihood without intervention) | `MEDIUM` (15%–50%) | `LOW` (<15%).
- **Impact Analysis:** Detailed failure outcome if unmitigated.
- **Actionable Mitigation Strategy:** Engineering safeguards and architectural designs to prevent occurrence.

## 2. EXHAUSTIVE RISK MATRIX

| Risk ID | Category | Risk Description | Severity | Probability | Impact | Mitigation Strategy |
|---|---|---|---|---|---|---|
| **RSK-01** | **Graphics Engine** | **Android GPU Texture Limit Overflow**<br>Loading uncompressed high-res camera photos (>4K) directly into Skia Canvas triggers OpenGL texture allocation failures (`GL_OUT_OF_MEMORY`) or black screen artifacts. | **CRITICAL** | **HIGH** | Instant app crash on lower-tier Android devices (Mali GPUs with 2048px texture limits). | Enforce mandatory image downsampling in `imageFiles.ts` to `MAX_WORKING_DIM = 2048px`. Automatically clamp textures before passing to Skia `useImage`. |
| **RSK-02** | **Graphics Engine** | **Skia Offscreen Surface OOM During 300 DPI Export**<br>Allocating a $2480 \times 3508$ px RGBA_8888 bitmap buffer for A4 300 DPI export requires ~34.8 MB of contiguous native heap memory per frame. | **HIGH** | **MEDIUM** | Low-RAM devices (3GB RAM) throw Java OutOfMemoryError during export. | Allocate offscreen surface inside a temporary scoped block; immediately call `.dispose()` or flush Skia image snapshot to disk; avoid retaining multiple snapshots in JS memory. |
| **RSK-03** | **Coordinate Alignment** | **Spatial Drift Across Multi-Overlays**<br>Floating-point rounding errors during pan/pinch zoom cause grid lines and Loomis construction lines to drift out of alignment with the underlying reference image. | **HIGH** | **HIGH** | Overlays appear offset from reference landmarks, ruining physical drawing accuracy. | Anchor all overlay primitives strictly to normalized Reference Image Space `[0..1, 0..1]`. Apply a single master 3×3 matrix transform at the parent `<Group>` level in Skia. |
| **RSK-04** | **Native Android** | **Process Death & Foreground State Loss**<br>When the user switches to the system Camera or background apps, Android OS kills the app process under memory pressure, wiping in-memory layers. | **CRITICAL** | **MEDIUM** | Complete loss of uncommitted drawing strokes and active overlay slider configurations. | Implement automatic project state debounced autosave (300 ms debounce) into SQLite WAL database upon any parameter change; persist active layer snapshot. |
| **RSK-05** | **Native Android** | **ARM64 Native Architecture Regression**<br>Accidental modification of `android/gradle.properties` reverting `reactNativeArchitectures` to include x86 or missing arm64-v8a ABI. | **CRITICAL** | **LOW** | "App isn't compatible with your phone" installation rejection error on physical Android smartphones. | Lock `reactNativeArchitectures=arm64-v8a` in `gradle.properties`; enforce CI check running `aapt dump badging` verifying `arm64-v8a` presence on every APK build. |
| **RSK-06** | **Image Processing** | **Whiteout Shader Incompatibility on Legacy GPUs**<br>Older Adreno or Mali GPU drivers failing to compile custom SkSL Runtime Shaders or misinterpreting `mix()` and `clamp()` functions. | **HIGH** | **MEDIUM** | Reference image renders as pure black or transparent when Whiteout slider is touched. | Provide a two-tier fallback: Compile SkSL Runtime Shader first; if compilation throws, fall back to a native Skia `ColorMatrix` filter that approximates linear whiteout. |
| **RSK-07** | **Print Accuracy** | **Printer Margin Clipping & Non-1:1 Scaling**<br>Physical printers applying automatic "Scale to Fit" or 5 mm hardware edge margins, distorting physical millimetre grid dimensions. | **HIGH** | **HIGH** | Physical ruler on paper does not match digital grid spacing (e.g., 20 mm digital grid prints as 18.8 mm). | Include a 50 mm calibration ruler graphic on the printed sheet's border; display explicit printing instructions ("Select 100% Scale / Do Not Fit to Page") in the Print Studio. |
| **RSK-08** | **Storage & Database** | **SQLite Migration Failure Breaking Existing Projects**<br>`ALTER TABLE projects ADD COLUMN` failing on existing production databases or causing null pointer exceptions when deserializing legacy JSON. | **CRITICAL** | **MEDIUM** | User opens app after update and finds all their previous drawing projects corrupted or inaccessible. | Write robust migration guard in `database.ts` verifying column existence with `PRAGMA table_info(projects)`; supply safe default values for all new columns (`paper_size = 'A4'`). |
| **RSK-09** | **Performance** | **Gesture Contention in Multi-Overlay Workstation**<br>Finger pan gestures conflicting between canvas viewport navigation (pan/zoom) and individual overlay control handles (e.g., dragging Loomis center or VP). | **MEDIUM** | **HIGH** | User tries to move the head construction circle, but the entire canvas pans instead, causing intense frustration. | Implement explicit mode toggle ("Navigate Canvas" vs "Adjust Overlay Guides"); enforce hit-testing with generous 24dp touch radius around active handles before activating canvas pan. |
| **RSK-10** | **Performance** | **JS Thread Starvation from Real-Time Analysis**<br>Running image analysis or Catmull-Rom stroke smoothing synchronously on the React Native JS thread during active drawing. | **HIGH** | **MEDIUM** | Drawing stroke latency exceeds 16 ms, causing visible cursor lag and jagged lines. | Run all Catmull-Rom spline calculations in optimized C++ via Reanimated worklets or offload heavy pixel analysis to background async tasks. |
| **RSK-11** | **Offline & Privacy** | **Accidental Background Cloud Upload of Private Images**<br>A background process or telemetry service sending local reference photos or drawing strokes to external cloud AI servers without consent. | **CRITICAL** | **LOW** | Severe privacy violation and breach of user trust; violation of Google Play User Data policies. | Enforce strict network isolation: Cloud AI adapters (`CloudHttpProvider`) are strictly invoked inside user-initiated button press callbacks. No automatic background sync. |
| **RSK-12** | **Offline & Privacy** | **Cloud Dependency Deadlock in Remote Locations**<br>A critical drawing feature hanging indefinitely when the artist is drawing outdoors or in an art studio with no Wi-Fi or cellular service. | **HIGH** | **LOW** | Tool displays infinite spinner or crashes when offline. | All 27 tools and 16 AI capabilities have 100% offline local mathematical or heuristic fallbacks (`LocalFallbackProvider.ts`, regex voice parser) with a strict 3.5s network timeout. |
| **RSK-13** | **Security & Auth** | **JWT Access Token Expiration Mid-Session**<br>Backend token expires while an artist is working, causing unhandled 401 errors that block saving projects. | **MEDIUM** | **LOW** | Annoying auth modals interrupting the creative drawing flow. | Local drawing projects, reference editing, and physical export require zero authentication and operate 100% locally. Auth is strictly required only for cloud AI credits and subscription sync. |
| **RSK-14** | **Testing Gaps** | **Lack of Physical Print Verification**<br>Automated tests verify bitmap pixels and math, but cannot verify whether physical inkjet printers faithfully reproduce the 1:1 millimetre scale. | **MEDIUM** | **HIGH** | Real-world artists discover scaling discrepancies that automated tests missed. | Create a standardized printable PDF test chart with 10 mm, 25 mm, and 50 mm calibration markers to be verified against physical steel rulers on physical hardware. |
| **RSK-15** | **UI/UX & Cognitive** | **Feature Overload for Novice Artists**<br>Presenting all 27 tools, vanishing points, and millimetre controls on a single screen overwhelms beginners, leading to immediate app abandonment. | **HIGH** | **HIGH** | High churn rate among beginners who wanted simple drawing guidance. | Strictly enforce Beginner Mode on first launch: Curate the 12-step guided pathway, hide CAD workstation controls, and use progressive disclosure to reveal advanced tools only when mastered. |

## 3. RISK MONITORING & MITIGATION PROTOCOL

1. **Pre-Commit Checks:** Every code modification must execute the 21 client Jest suites and 10 backend Jest suites. Zero regressions allowed.
2. **Native Memory Profiling:** Every release candidate must undergo 30 minutes of continuous multi-overlay rendering on an Android test device while monitoring Android Profiler heap metrics.
3. **Hardware Fallback Guarantees:** Any advanced GPU feature (SkSL shaders, floating-point textures) must include an automated fallback path to basic Skia primitives if native initialization fails.
